# Notification capture device test

This checklist is for a custom DealStasher build. It is not a substitute for
testing in Expo Go.

## Why a custom build is required

Expo Go cannot exercise the native notification-capture paths:

- Android Notification Access depends on the `NotificationListenerService` and
  the `DealStasherNotificationCapture` native module added by
  `plugins/withNotificationCapture.js`. Those are compiled into a custom
  Android build, not into Expo Go.
- iOS sharing depends on the app-specific Share Extension generated by the
  `expo-sharing` config plugin. The extension is part of a custom iOS build,
  not the Expo Go app.
- A successful Expo Go launch only verifies the JavaScript UI. It does not
  prove that Android can capture notifications or that DealStasher appears in
  the iOS share sheet.

Use a development or store-like build that has been rebuilt after any changes
to `app.json` or a config plugin. Test with the app installed on a physical
device; simulators do not provide a representative notification/share path.

## Android: capture while DealStasher is closed

**Prerequisites**

- Physical Android device
- Custom DealStasher Android build
- A second app that can generate a visible notification, such as Messages,
  email, or a test notification tool

1. Install or update the custom build and sign in.
2. Open **Profile → Notification access**. Enable DealStasher in Android's
   **Notification access** settings.
3. Return to DealStasher. The profile row must say
   **Connected · capturing new notifications**.
4. Fully close DealStasher from the recent-apps screen.
5. Send a notification with distinctive test content, for example:
   - title: `DealStasher Android capture test`
   - body: `Unique body 2026-09-10`
6. Reopen DealStasher. Open the stash, or use **Profile → Refresh captures**.
7. Confirm that exactly one notification is present and that the app name,
   title, body, and captured time are preserved. Confirm the notification is
   still present after navigating away and back.

**Revocation check**

1. Open Android **Notification access** settings and disable DealStasher.
2. Return to the app and wait for the profile to refresh, or leave and reopen
   the profile. The row must no longer say connected and must prompt to enable
   access.
3. Send a second distinctive notification while access is disabled.
4. Refresh captures and confirm the second notification is not added.
5. Re-enable access and repeat the closed-app check once more.

Record the Android model, OS version, build identifier, and pass/fail result.

## iPhone: import shared text and links

**Prerequisites**

- Physical iPhone
- Custom DealStasher iOS build containing the Share Extension
- Notes, Safari, Messages, or another app that exposes the iOS Share Sheet

### Shared text

1. Kill DealStasher so it is not running.
2. In Notes or Messages, create content with distinctive text, for example:
   `DealStasher iPhone text test — preserve this exact line`.
3. Select the text, open the Share Sheet, and choose DealStasher.
4. Allow the app to cold start if prompted.
5. Confirm one new item appears in the stash. Confirm the imported title/body
   preserves the shared content and that the app does not crash.
6. Return to the source app and share the same selection again only if testing
   duplicate handling. A single share event must create one item.

### Shared link

1. Kill DealStasher again.
2. In Safari, share a URL such as
   `https://example.com/dealstasher-ios-test`.
3. Choose DealStasher from the Share Sheet.
4. Confirm one new item appears, the URL is preserved, and its **Open offer**
   action is available.

The profile copy should explain that iOS imports only content the user
explicitly shares; it does not passively read other apps' notification history.

Record the iPhone model, iOS version, build identifier, and pass/fail result.

## Release gate

The notification-capture work is ready for release only when all of these are
passed on physical devices:

- Android captures a new notification while DealStasher is closed.
- Android revocation changes the profile status and prevents new captures.
- iOS shared text imports once with its content intact.
- iOS shared links import once with the URL intact.
- iOS cold-start sharing does not crash or lose the payload.

If a check cannot be run because a physical device or custom build is
unavailable, mark it **blocked**, not passed.
